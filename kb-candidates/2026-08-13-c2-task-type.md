## 1 · A write is a hypothesis until you have read it back — and the dangerous failure is the one that returns success to a channel you are not reading

**Claim.** A write to a shared artifact is not done when the write command returns; it is done
when a **read-back matches what you intended to write**. The failure mode that matters is not the
loud one — it is the write that fails *after* you have formed the belief that it succeeded, in a
channel your control flow does not inspect. Verify by fetching the artifact again and diffing it
against the exact bytes you sent. This is the write-side of *"a source-read diagnosis is a
hypothesis"*: there, a **model of the system** was confirmed against the running system; here, a
**model of your own effect on the system** is.

**Why.** Observed 2026-08-13 while appending one decision line to GitHub issue `#12`, the
wayfinder map. The map's body has grown to **103 KB** over 22 resolved tickets, and
`gh api … --method PATCH -f body="$(cat file)"` now dies with **`Argument list too long`** — the
shell's `ARG_MAX`, not GitHub's. The command emitted its error, but the surrounding step had
already moved on to *"the map is updated"*; the write had done **nothing**, and the only thing
that caught it was a round-trip `diff` run for a different reason (verifying the append was a
*pure insertion*, per this map's commons discipline). Fixed by `--input <file.json>`, which passes
the body through a file rather than `argv`.

Three properties make this worth a page rather than a note:

1. **It scales in silently.** Nothing changed in the command; the *document* grew past a limit
   nobody was watching. Every earlier session on this map ran the same call successfully, so the
   failure arrives at a session that has precedent telling it the call is fine.
2. **The safety check that caught it was aimed elsewhere.** The purity diff exists to catch a
   *concurrent sibling* clobbering the commons, not a failed write. A verification instrument
   caught a defect outside its own remit — which is the argument for cheap read-backs generally.
3. **It is invisible to every other guard.** No exception propagates, no exit code is inspected,
   no test covers a `gh` call, and the artifact is outside the repo so no `git status` shows it.

**Rejected alternative:** *"check the exit code"* — insufficient in general and insufficient here.
The call was one step of a compound command; and an API write can return `200` and still not
contain what you meant (truncation, encoding, a concurrent overwrite between your read and your
write). Only the read-back tests the property you actually care about.

**Destination.** `C:\Dev\JARVIS\kb\dev\runtime-verification.md` — a new section, **not** a new
page. That page already owns the principle in its read-side form (*a root cause derived by reading
code is a hypothesis; confirm it at runtime*), and this is the same principle applied to writes;
splitting them would put one idea on two pages. Check for overlap with
`kb/dev/recovery-masks-failure.md` (a failure that leaves no evidence) — related but distinct: that
one is about *good error handling* hiding a fault, this one is about *no error handling at all*.

**Anchors.** This repo — `b9d1be7` (the resolution commit, whose changelog and `SESSIONS.md`

## 2 · The fork check must run against the code, not against the ticket's own statement of the fork

**Claim.** `rules/question-axis-naming.md` requires grepping for a write path between two
quantities *"one hop wider than the two you named"* before drafting options. That rule is written
as if the two quantities come from **you**. When they come from a **committed artifact** — a
ticket, a spec, a brief — the widening has to start at the artifact's *premise*, not at its
*terms*, because the artifact states the fork as settled background rather than as a question, and
a premise stated as background is never re-derived. The tell is that the check **passes**: you
widen correctly around the two named quantities, find nothing, and never notice the fork's second
half was aimed at an object that cannot hold it.

**Why.** Observed 2026-08-13 on `#20 · C2`, whose title *is* the fork: *"is it a second axis or a
replacement for life areas?"* Four options were drafted, all varying along **which consumer would
read the new field**, and the fork-check was run over that axis and passed. Ido refused the picker
outright — *"I couldn't fully understand you or what each option means"* — and handed the decision
back. Deriving it instead took **three greps of `domain/model/`** and falsified the premise: the
app already ships `GoalCategory` (closed, ten, app-authored, model-assigned) beside `LifeArea`
(open, user-authored) as **two answers to one question on the same object**, with `Mappers.kt:29`
quietly resolving the conflict. So *replacement* had already happened, to a different field than
the one under discussion, and no option in the set could reach it.

Two things distinguish this from the failures already recorded in the rule:

1. **The axis was named and the naming did not help.** The question text explicitly named the axis
   (*consumers*) and listed the axes considered and dropped. Naming an axis tests whether your
   options span it; it cannot test whether the *question* is about a real distinction.
2. **The refusal was the only signal, and it was ambiguous.** Under the existing tell table,
   *"I couldn't understand the options"* routes to hand-back → ownership → premise → form →
   density. Premise is step 2 and would have caught it — but only if *"re-run the fork check"* is
   read as *re-run it against the world*, not *against the same two terms*. The proposed clause
   makes that explicit.

**Rejected alternative:** *"read the ticket more carefully"* — this ticket was read carefully; its
own **What it must settle** block is what supplied the four consumers, and it was written before
five of the decisions that killed three of them. Care does not fix a premise; a grep does.

**Destination.** `C:\Dev\JARVIS\rules\question-axis-naming.md` — a clause on **The widening**,
extending it from *derivation closures in code* to *premises in committed artifacts*.
