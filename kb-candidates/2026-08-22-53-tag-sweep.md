## 1 · A platform call inside a "pure" seam fails toward a **passing** test

**Claim.** When a function that a unit test exercises reaches a platform API that throws off-device,
the failure does not surface as an error — it surfaces as **every input returning the fallback**. And
that is not symmetric: a test asserting *these values are different* fails loudly, while a test
asserting *these values have become the same* **passes for the wrong reason**.

`Observed:` 2026-08-22, GoalPilot `#53`. `ui/components/ColorExt.kt`'s `String.toComposeColor` used
`androidx.core.graphics.toColorInt`, which calls `android.graphics.Color.parseColor` and throws under
a plain JVM unit test; the call site wrapped it in `runCatching { … }.getOrDefault(fallback)`. So in
`CategoryTagTest` all ten `GoalCategory` fills resolved to one grey. The test written that day
asserted §4.1's `.tag` premise — *dark neo collapses the categorical hues into one ramp* — and **that
assertion would have been green on a build where the collapse was never applied at all.** It was
caught only because the *paired* assertion in the same test (*identity keeps them apart*) failed
first, which is luck about test ordering rather than a property of the guard.

**Why (and what was rejected).** *Rejected:* keep `toColorInt` and use Robolectric for this test —
that buys the android layer back at the cost of the thing being tested, and the rest of the file was
already hand-rolled precisely to avoid it (its own closing comment says `ColorUtils` "throws under a
JVM unit test"). *Rejected:* assert on hex strings instead of `Color`s — the point is to run the
**real** function, and a test that stops short of it is the copy-of-the-code antipattern
`ThemePaletteTest` exists to avoid. Fixed by hand-rolling a six-line hex parser, which also made
`categoryFill` JVM-runnable as a whole.

The generalisable half: **a swallowed exception plus a total fallback is an instrument that reads
"all equal", and "all equal" is a passing result for any test about convergence, collapse,
deduplication or idempotence.** The tell is not in the output; it is that one seam in an otherwise
pure module still imports the platform.

**Destination.** `kb/dev/look-at-your-own-output.md` — a new subsection under §4, alongside the
existing "check the instrument itself on the hardest input it exists for". This is that rule with a
specific mechanism: the instrument degrades to a constant, and a constant satisfies a sameness
assertion.

**Anchors.** `app/src/main/java/com/idomarhaim/goalpilot/ui/components/ColorExt.kt` ·
`app/src/test/java/com/idomarhaim/goalpilot/ui/CategoryTagTest.kt` ·
`CHANGELOG/2026-08-22/53-tag-sweep.md` §6a.

**Supersedes.** Nothing. Extends `look-at-your-own-output.md` §4 rather than rewriting it.

## 2 · A dying emulator reports as **test failures**, and the render passes **pass**

**Claim.** An Android emulator degrading before it disconnects produces a run whose signals point
away from the real cause. `Observed:` 2026-08-22, GoalPilot `#53`, AVD `Pixel_10_Pro_XL`:

- the instrumented suite came back `204 run, **6 failures**`, all in one unrelated test class, all
  reading `expected: -65536 but was: 0` — a captured pixel of nothing;
- **the render passes in the same run PASSED.** They assert the written PNG has `length > 0`, and a
  blank PNG has `length > 0`. The 16 frames totalled **33 KB** where a healthy run writes **2.4 MB**;
- minutes later `adb` reported `device 'emulator-5554' not found`.

So the only honest signal in the room was the six "failures", and the instinctive reading of them —
*my change broke that other session's work* — was **wrong**. The cheap discriminator is the **frame
size**, and it takes one `ls -la`: a blank capture is one to two orders of magnitude smaller than a
real one.

Two practical notes from the same run. **`am instrument -w` buffers everything until the end**, so a
stalled run and a slow one are indistinguishable — pass **`-r`** and the runner streams
`INSTRUMENTATION_STATUS: current=<n>` per test, which turns "is it hung?" into one `grep`. And a
timed-out host-side `am instrument` does not necessarily stop the on-device instrumentation, so a
second invocation can contend with the first.

Recovery that worked: `taskkill` on `qemu-system-x86_64.exe` and `emulator.exe` (an `adb emu kill`
left both running), then `emulator -avd <name> -no-snapshot-save -no-boot-anim
-gpu swiftshader_indirect`. **No `-wipe-data`,** so the app's own data — and the Firebase auth store
a sign-in lives in — survived; `pm list packages` confirmed both APKs still installed afterwards. The
software GPU is slower and did not crash again.

**Why (and what was rejected).** *Rejected:* strengthening the render passes to assert a minimum byte
count — a threshold that varies by material, skin and screen, and it would still be a proxy. The
honest fix is that a render pass's assertion is *"a file was written"* and its **verification is a
human looking at the frame**, which is what the pass is for; the byte count is a fast triage signal,
not a gate.

**Destination.** `kb/dev/android-device-verification.md` — a new section on reading a suspicious run,
beside §8's `install -r` + `am instrument` path (which this session used throughout, and which again
preserved everything).

**Anchors.** `CHANGELOG/2026-08-22/53-tag-sweep.md` §6b ·
`app/src/androidTest/java/com/idomarhaim/goalpilot/ui/CategoryPaletteRenderPass.kt`.

**Supersedes.** Nothing. Adds to `android-device-verification.md`; does not touch §6.2, which

## 3 · A chart label rule whose answer depends on **where** the mark sits is a bug you will ship

**Claim.** When labelling marks arranged around a shape, a fit test that keeps the text
**axis-aligned** makes the answer a function of the mark's *angle*, and the result reads as a
rendering fault rather than as a rule. Rotating the text so its own axes line up with the mark's
removes the angle from the problem entirely, and the fit then depends only on how big the mark is —
which is what it should have depended on.

`Observed:` 2026-08-22, GoalPilot `#53`, donut wedge labels. A horizontal six-letter word is ~32 dp
and the ring band is 34 dp, so exact projection arithmetic (`w·|cos α| + h·|sin α|` radially,
`w·|sin α| + h·|cos α|` tangentially) said **yes at 12 and 6 on the clock and no at 3 and 9**. The
arithmetic was right; the design was wrong. Laying the word along the tangent made the band's
thickness always face the word's height and the arc always face its width.

**The second half is the one that needed a frame.** With rotation, the rule still drew only words
that fitted **whole**, and the render pass showed it labelling **six of ten** equal wedges — leaving
the four *longest names* blank. Under a material that has collapsed the hues, those were the four
marks nothing else could tell apart. **A rule that goes quiet exactly where it is needed is not a
rule**, and no amount of padding arithmetic fixes it because the variable was never the padding: a
long name was being treated as an unlabellable mark. Measuring with `TextOverflow.Ellipsis` against
the room available, and judging the **room** rather than the finished string, labels all ten.

The floor for "shortened too far" is expressed in multiples of the **type's own height**, not in dp,
so it follows the device's font scale instead of fighting it — and it was wrong at first for a
reason worth stating: a glyph's advance is roughly **half** a line height, so `3×height` demanded
about six glyphs and refused a 40 dp column outright.

**Why (and what was rejected).** *Rejected:* a callout gutter outside the ring — it costs about a
third of the chart's width on a phone, shrinking the ring the rule is trying to make readable, and at
ten marks the callouts collide and need a de-collision pass with its own failure modes. *Rejected:*
shrinking the type until whole words fit — that trades a legibility rule for a legibility failure.

**Destination.** `kb/dev/` — a new page, `chart-labels-must-not-depend-on-angle.md`, or a section on
an existing Compose-charting page if one exists. Ingest should check first.

**Anchors.** `app/src/main/java/com/idomarhaim/goalpilot/ui/components/DonutChart.kt`
(`wedgeLabelRoom`, `wedgeLabelFits`, `tangentRotation`) ·
`docs/render-passes/2026-08-22-53-tag-sweep/README.md` · `CHANGELOG/2026-08-22/53-tag-sweep.md` §3.

**Supersedes.** Nothing.

**Status.** Ready to ingest.
