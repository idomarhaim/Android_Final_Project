# Surfacing repository error text — right for refusals, wrong for transport

**TL;DR:** This codebase's `Resource.Error` convention passes the data layer's own
message straight to the user, and that is **correct** when the message is *domain*
text the user can act on. It is wrong when the message is *transport* text. The line
is who generated the failure:

| The failure was generated by | Show | Example |
|---|---|---|
| the **domain** — a refusal with a reason | the repository's own message | *"No user with that code"*, *"Join the challenge before reporting a score"* |
| the **network / transport** | a written message; keep the original in the log | `UNAVAILABLE: Unable to resolve host firestore.googleapis.com` |

*Provenance: session `fix-task-completion-feedback`, 2026-08-08 — GitHub issue
[#3](https://github.com/idomarhaim/Android_Final_Project/issues/3). See
`CHANGELOG/2026-08-08/fix-task-completion-feedback.md` → "A second defect the
measurement exposed".*

## Why this is a refinement, not a correction

The convention was **right**, and the call site was following it correctly, and the
result was still a snackbar reading
`UNAVAILABLE: Unable to resolve host firestore.googleapis.com` on a real screen.

That is what makes it worth writing down. It is not a mistake in *applying* the
house rule — it is a boundary case *inside* it, which nothing in the rule's original
statement excluded. The rule as it now stands:

> Surface repository text for refusals **the domain generated**. Substitute a
> written message for failures **the network generated**, and keep the original in
> the log.

## Why only a real screen caught it

It passed unit tests and it passed review. Both were checking that the error
*reached the user* — which it did. Neither had any way to notice that the string
which reached them was a gRPC status line, because at the call site it is just the
`message` field, and the offline path that produces it is not the path a test
exercises by default.

The regression test that now holds it is named for the user-visible property, not
the mechanism: *"the raw gRPC failure text never reaches the user"*.

## Where the convention lives

`SocialViewModel.report` is the reference implementation of the *domain* half —
check it before writing new error handling, and extend it rather than inventing a
second convention beside it.

**Promotion note:** this stays project-local deliberately. It is about *this*
codebase's `Resource` convention; promote it to the central bundle only if a second
project shows the same shape.
