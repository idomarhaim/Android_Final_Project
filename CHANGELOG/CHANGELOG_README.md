# Changelog

**One folder per day, one file per session:** `CHANGELOG/YYYY-MM-DD/<session>.md`,
so parallel sessions never write the same file. Entries dated 2026-08-03 and earlier
predate that convention and are flat `YYYY-MM-DD.md` files; both forms are listed
below, and **2026-08-03 has both** — the migration let the last partly-flat day
finish flat and made every later day a folder.
Each entry summarises what changed, why, and — per the testing discipline — a
`## 🧪 Tests` section with pass/fail counts and covered layers.

## How this page is maintained

It has three parts, and **the first one is not maintained by hand at all.**

1. **The day index is generated** by [`scripts/New-ChangelogIndex.ps1`](../scripts/New-ChangelogIndex.ps1)
   from the day folders themselves, and a pre-commit hook refuses a commit whose
   changelog file the index does not list. **Never hand-edit between the markers** —
   the next run overwrites it. Each session's line is read from that session's own
   mandatory `> **Summary:**` line, so no two sessions ever write the same line.
   A file with no `Summary:` gets a bare link rather than invented prose; the gap
   is meant to be visible.
2. **Archive** — the seven flat pre-2026-08-04 day files. The generator walks day
   *folders* and cannot see them, so their rows stay hand-written. Nothing
   migrates: that is history, not drift.
3. **Long-form notes** — the hand-written per-session descriptions that *were* this
   index until 2026-08-17, kept **verbatim**. They cover 2026-08-03 → 2026-08-10
   only and are deliberately **not** exhaustive; the generated table is what
   guarantees coverage. Nothing was trimmed or reworded when it moved.

Writing your entry, in one command — **stage your own changelog file first**, because
the generator reads the git index, not the working tree:

```powershell
git add CHANGELOG/<day>/<session>.md; `
powershell -File scripts\New-ChangelogIndex.ps1 -Staged; `
git add CHANGELOG/CHANGELOG_README.md
```

Hooks are not version-controlled by git, so a fresh clone installs them once with
`powershell -File scripts\Install-GitHooks.ps1`.

**Why it changed (2026-08-17, session `changelog-index-backfill`):** the hand-written
list stopped on 2026-08-10, and **46 of 75** session files had no row — including
every session from 08-15 and 08-16, the repo's two busiest days. A hand-appended
index over a sharded log is a shared singleton that every session has to remember,
and forgetting it is silent. Generating it removes the contention rather than
serialising it — `rules/agent-topology-and-model-routing.md` §5.2, *shard before you
lease*.
