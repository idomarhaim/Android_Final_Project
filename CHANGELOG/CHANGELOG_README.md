# Changelog

**One folder per day, one file per session:** `CHANGELOG/YYYY-MM-DD/<session>.md`,
so parallel sessions never write the same file. Entries before 2026-08-03 predate
that convention and are flat `YYYY-MM-DD.md` files; both forms are listed below.
Each entry summarises what changed, why, and — per the testing discipline — a
`## 🧪 Tests` section with pass/fail counts and covered layers.

- [2026-08-06/product-review.md](2026-08-06/product-review.md) — `product-review` session: the pre-sleep product/UX brief becomes a citable backlog — a faithful English transcription (`R1`–`R28`), the actionable half split from the 13 product-model decisions bound for a `/wayfinder` map, and the finding that the reported task-score/goal-percentage "bug" is two independent numbers by construction, not a defect.
- [2026-08-07/product-device-pass.md](2026-08-07/product-device-pass.md) — `product-device-pass`, **second sitting**: re-claimed to close the first-run empty states with an approved `pm clear`. It did **not** reach the zero-data states — signing back in restores everything from Firestore — but it did find `A10`, that a cold cacheless load is a blank page and an 8-pixel dot for ~10 s, which is what a new phone or a reinstall actually shows. Plus the environment trap that `pm clear` wedges Play Services on this emulator, and how to tell that apart from a hung app in one command.
- [2026-08-06/product-device-pass.md](2026-08-06/product-device-pass.md) — `product-device-pass` session: the product/UX backlog meets a real build — `D2`/`D3`/`D4`/`D5` confirmed on the emulator and filed as the repo's first GitHub issues (`#2`–`#11`), `D1` reclassified as an undecided model rather than a bug (a challenge's score has exactly one writer, and `ChallengeType` is decorative), and `D3` measured at ~2 s with the cause found: `setDone` is a server-only Firestore **transaction** whose `Resource` the ViewModel discards — which is also why the same tap does nothing at all offline.
